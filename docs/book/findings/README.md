# Findings

*Companion to **[Hands Inside the Instrument](../README.md)** and the **[Control-Methods Sourcebook](../CONTROL_METHODS_SOURCEBOOK.md)**.*

The book builds intuition and ends each chapter with an open question. The Sourcebook ranks the methods to reach for. **This folder is what happens after you reach** — dated notes from actually reading a paper closely, checking it against our code, or running a probe. A finding may *supersede* a Sourcebook line (e.g. "paper-only, reimplement it" → "we already have a near-faithful port; here are the three gaps").

Each note keeps the house rule: where a closer look corrected an over-optimistic claim, the **corrected** version is kept, not the cheerful one. Each ends by opening the next question rather than closing one.

## Notes
- [2026-06-25 — Chroma steers — the first content control, and the 3-way taxonomy](2026-06-25-chroma-steers-and-the-control-taxonomy.md) — a chroma LatCH head (cosine, SAME (3,128,T) `other`-stem target) **steers output pitch**: all-C vs all-F# palettes make the requested pitch class **dominant** in the decoded audio (gain ~1536–2048, monotonic; re-measured with `same_chroma`). Readout cos **0.89** temporal vs 0.14 linear (the §6 pattern). Completes the **control taxonomy**: amount/density steers (moderate gain), content/pitch steers (high gain), structure/timing (beat/downbeat) doesn't. Validates §8's dense-vs-sparse + the handoff's chroma-regularised-latent prediction.

- [2026-06-24 — SA3 on AMD via ONNX: a VRAM win, not a speed win](2026-06-24-sa3-onnx-on-amd-vram-not-speed.md) — exported the SAME AE **and** the medium-base DiT to ONNX, GPU-verified on the 9070 XT (MIGraphX), and benchmarked vs native torch. Verdict: the port is a **VRAM/deployment win, not speed** — eager torch is **~3.3× faster** per DiT call (0.707 s vs 2.314 s loop; MIGraphX doesn't beat torch's rocBLAS/MIOpen), but ONNX runs in **3.8 GB with zero torch dependency** (coexists with a training job), same quality (z0 cos 0.9993). Three corrections kept (house rule): a **cos-1.0 export that validated against its own omission** (the DiT's 257-ch `local_add_cond` must be fed, not `None`); the **`migraphx_fp16_enable` EP "fix" that OOM'd harder** (loads fp32→quantizes) — the real fix is **fp16-*exported* files** (3.8 GB, cos 0.99999); and the **expected speed win that was a VRAM win**. Runtime finding (beside the Sourcebook); tooling in `stable-audio-3/`.
- [2026-06-23 — Curated-reference rewards & the SAME-L steerability map](2026-06-23-curated-reference-rewards-and-the-same-l-steerability-map.md) — three runs: Audiobox aesthetics are a genre-biased **collapse-floor, not a reward**; a **curated reference set is a genre-neutral reward** (MERT-separation AUC 0.999 vs default output, ~0.87 within-genre at layers 5–6); and the **measured SAME-L steerability map** (spectral easy ~0.8, rhythm hard — **downbeat R² 0.16**, which *explains the riffer's rhythm-transfer failure*). Plus the multi-band MERT-conditioner design — and the gating probe, now **run**: **MERT exposes rhythm where SAME-L hides it** (beat 0.36→**0.83**, onset →0.71, downbeat →0.39, all at MERT layers ~1–6; spectral/chroma show no MERT gain). **Then corrected (§6):** a **temporal 1D-CNN head on the latent matches/beats MERT** (beat 0.86, onset 0.81, downbeat 0.58) — the latent never hid rhythm, the per-frame *linear* probe just couldn't see it. So **you don't need MERT for rhythm — build a temporal LatCH head** (no finetune); MERT's niche narrows to the reference-*style* reward. Lesson: LatCH heads for temporally-structured features must be temporal, not per-frame. **Then built it (§7):** trained an **onset LatCH head** (production arch — already temporal) and it **steers generation** — requested onset vs measured **corr 0.986, monotonic** (medium-base, gain 48); moderate authority, widens with gain. A working rhythm control, no MERT/finetune. **Then the boundary (§8):** beat + downbeat heads train fine but **don't steer** — constant target flat, time-varying pulse target a no-op (output ≈ baseline, wav |Δ|~1%, tempo unchanged). **Trainability ≠ steerability:** training-free guidance steers *dense amount* features (onset/RMS/brightness — strong gradient) but not *sparse structural* ones (beat/downbeat placement — gradient can't reorganise the latent). Rhythm *structure* needs trained beat-grid conditioning, not head guidance. Advances Sourcebook §Ch13 (relational head) / §Ch8 (conditioner).
